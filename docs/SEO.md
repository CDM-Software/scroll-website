# SEO — правила проекта

Свод правил для всех, кто правит сайт, включая ИИ-агентов. Проверяемая часть
вынесена в `npm run seo` (`scripts/seo-audit.mjs`) — он разбирает собранный
HTML и падает на ошибках. Правила ниже объясняют, **почему** так, и покрывают
то, что скриптом не проверить.

Сайт русскоязычный в первую очередь: русский на корне, английский на `/en`.
Основной поисковый спрос — русский, поэтому приоритет у русских текстов.

---

## 1. Что уже настроено — не сломать

| Механизм | Где | Что случится, если сломать |
|---|---|---|
| `metadataBase`, canonical, hreflang | `[locale]/layout.tsx` + `lib/site.ts` | дубли страниц в индексе, склейка не туда |
| `sitemap.xml` | `app/sitemap.ts` | новые страницы не попадут в индекс |
| `robots.txt` | `app/robots.ts` | закрытие сайта от индексации |
| OG-картинка | `[locale]/opengraph-image.tsx` | превью ссылок без картинки |
| Исключение `opengraph-image` из middleware | `middleware.ts` | og:image начнёт редиректить, превью сломается |
| JSON-LD Organization + WebSite | `[locale]/layout.tsx`, `lib/schema.ts` | потеря знаний о бренде |
| JSON-LD FAQPage | `[locale]/page.tsx` | потеря расширенного сниппета в выдаче |
| `theme-color` | `viewport` в `[locale]/layout.tsx` | косметика мобильного браузера |

Единственный источник адреса сайта — `SITE_URL` в `src/lib/site.ts`. Домен
нигде больше не хардкодить.

## 2. Чек-лист новой страницы

1. `generateStaticParams` по `routing.locales` — страница должна быть
   статической, а не рендериться на запрос.
2. `generateMetadata` с `title`, `description`, `alternates.canonical`
   и `alternates.languages` (включая `x-default`). Образец —
   `lib/legal.ts` + `[locale]/privacy/page.tsx`.
3. Ровно один `<h1>` с главным смыслом страницы.
4. Путь добавлен в `PATHS` в `app/sitemap.ts`.
5. На страницу ведёт хотя бы одна внутренняя ссылка (обычно из футера) —
   страница без входящих ссылок индексируется хуже.
6. Тексты в `messages/ru.json` и `messages/en.json`, оба языка заполнены.
7. `npm run build && npm run seo` — чисто.

## 3. Title, description, H1

**Title.** До 60 символов, иначе обрежется в выдаче. Формула:
«Суть страницы — уточнение». Шаблон `%s · ScRoll` подставляется автоматически
из layout, дублировать «ScRoll» в заголовке страницы не нужно.

**Description.** 70–160 символов. Это не фактор ранжирования, но напрямую
влияет на кликабельность: пишите пользу, а не перечень ключевых слов.
Уникальный для каждой страницы.

**H1.** Один на страницу, совпадает по смыслу с title, но не обязан совпадать
дословно. На лендинге h1 — слоган, а не название компании.

Ключевые слова из `meta.keywords` Google не использует с 2009 года. Поле
оставлено для прочих движков и как список тем, но раскладывать по нему
семантику бесполезно.

## 4. Заголовки

Иерархия без разрывов: за `h2` не может идти `h4`. Аудитор это проверяет.
Заголовок — это структура документа, а не способ сделать текст крупнее:
если нужен только размер, берите класс, а не уровень тега.

## 5. Структурированные данные

Схемы собираются в `src/lib/schema.ts`, вставляются компонентом
`components/seo/JsonLd.tsx` (он экранирует `<`, чтобы строка из переводов
не смогла закрыть тег `script`).

Что где:

- **Organization + WebSite** — в layout, на всех страницах. `legalName` —
  `CDM Software LLC`. Прежние названия (Circle of DMs, CDMS) в разметке
  запрещены, см. `PRODUCT-CONTEXT.md` §5.
- **FAQPage** — только на лендинге, где секция FAQ реально видна.

**Железное правило: размечать можно только то, что видно на странице.**
Разметка вопросов, которых нет в верстке, — повод для ручных санкций Google.
Поэтому FAQ-схема берёт данные из тех же `messages/*.json`, что и секция.

Чего пока сознательно нет:

- **SoftwareApplication / MobileApplication** — приложение ещё не в сторах,
  на лендинге стоит «Скоро в Google Play». Разметка приложения со ссылкой
  на несуществующую страницу магазина — ложное заявление. Добавлять, когда
  появится реальный листинг, вместе с `offers` и `aggregateRating`.
- **BreadcrumbList** — вложенности нет, все страницы первого уровня.
- **Review / AggregateRating** — рейтинги живут в приложении, не на сайте.
  Размечать чужие оценки на промо-странице нельзя.

Проверять готовую разметку: https://search.google.com/test/rich-results

## 6. Изображения

- Только `next/image` (обёртка `components/landing/Screenshot.tsx`), никаких
  голых `<img>` для контента. Формат и размеры подбирает Next.
- Осмысленный `alt` на каждой картинке: что на экране, а не «скриншот».
  Декоративные — `alt=""` плюс `aria-hidden`.
- Первому экрану (hero) — `priority`, остальным нет: иначе всё полезет
  в приоритетную загрузку и LCP просядет.
- `sizes` обязателен при `fill`, иначе браузер скачает самый большой вариант.
- Скрины приложения — настоящие экраны из Figma в 2x, лежат в `public/screens/`.

## 7. Ссылки

- Внутренние — только `Link` из `@/i18n/navigation`, иначе потеряется префикс
  локали и с `/en` ссылка уведёт на русскую страницу.
- Никаких `href="#"` в продакшене: для поисковика это ссылка в никуда,
  для читалки с экрана — тупик.
- Текст ссылки должен объяснять цель. «Подробнее» без контекста — плохо,
  «Найти игру» — хорошо.
- Внешние ссылки на чужие ресурсы — `rel="noopener"`; для непроверенных
  добавлять `nofollow`.

## 8. Локали и hreflang

Каждая страница обязана перечислить обе версии и `x-default`. Русская —
каноническая для `x-default`, потому что аудитория русскоязычная.

`localeDetection` включён: заход на `/` с английским `Accept-Language`
редиректит на `/en`. Для поисковиков это нормально — Googlebot ходит без
предпочтений языка и получает русскую версию. Побочный эффект: краулер
Telegram шлёт `Accept-Language: en` и показывает превью на английском.

## 9. Технические файлы

- `robots.txt` — генерируется из `app/robots.ts`, разрешает всё и указывает
  на sitemap. Закрывать что-то от индексации — осознанное решение,
  не побочный эффект правки.
- `sitemap.xml` — из `app/sitemap.ts`, список путей в константе `PATHS`.
  Обе локали каждого пути плюс `alternates`.
- `manifest.webmanifest` намеренно нет: на ранжирование не влияет, а промо-сайту
  не нужна установка как приложения.

## 10. Производительность

Core Web Vitals — фактор ранжирования. Что бережём:

- **Статика.** Все страницы пререндерятся на билде. Если в выводе `next build`
  страница помечена `ƒ` (dynamic) вместо `●`/`○` — это регрессия, чините.
  Исключение одно: `[locale]/[...rest]`, обработчик 404 для произвольных
  путей — он динамический по определению.
- **JS.** В проекте ровно один клиентский компонент (`Rise.tsx`). Новый
  `'use client'` — только если правда нужен браузерный API.
- **Шрифты.** Geist через `next/font`, self-hosted. Внешних шрифтовых CDN
  быть не должно — это лишний коннект и сдвиг макета.
- **CLS.** Картинкам всегда заданы размеры или `fill` с контейнером
  фиксированных пропорций.

## 11. Как проверять

```bash
npm run build && npm run seo
```

Аудитор проверяет на всех собранных страницах: наличие и длину title
и description, canonical, hreflang `x-default`, og:image и og:title, `lang`
у `<html>`, ровно один `h1`, разрывы в иерархии заголовков, `alt` у картинок,
ссылки-заглушки и без текста, парсится ли JSON-LD.

Ошибки роняют команду, предупреждения — нет. Предупреждение не значит
«можно забить»: значит «реши осознанно».

Чего скрипт не видит и что проверяется руками:

- осмысленность текстов и соответствие терминологии из `PRODUCT-CONTEXT.md` §5;
- реальные Core Web Vitals — Lighthouse или PageSpeed Insights на проде;
- корректность разметки — Rich Results Test;
- как выглядит превью ссылки — отправить в Telegram с новым query (`/?v=2`),
  чтобы обойти кеш.

## 12. Чего не делать

- Не размечать данные, которых нет на странице.
- Не набивать текст ключевыми словами. Тон задан в `PRODUCT-CONTEXT.md` §2.
- Не заводить второй `h1`, чтобы «усилить» заголовок.
- Не прятать текст для поисковика.
- Не менять URL существующих страниц без редиректа: потеря позиций.
- Не ставить `noindex` на прод-страницы «временно».
- Не подключать внешние скрипты аналитики без обсуждения: они бьют по CWV,
  а политика конфиденциальности описывает их наличие отдельно.

## 13. Открытые задачи

- **Ссылки на соцсети в футере — заглушки `href="#"`.** Нужны реальные адреса
  Telegram и YouTube. Заодно их стоит добавить в `sameAs` у Organization —
  это стандартный способ связать бренд с его аккаунтами.
- **Нет аналитики.** Ни счётчика посещаемости, ни Search Console. Без Search
  Console не видно, по каким запросам приходят и что выпало из индекса.
  Отметьте: политика конфиденциальности уже упоминает аналитические cookies —
  либо подключить аналитику, либо убрать этот абзац.
- **`SoftwareApplication` после релиза в сторах** — вместе с ссылками
  на листинги.
