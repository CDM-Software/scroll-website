# Правила работы в этом репозитории

Промо-сайт ScRoll: Next.js 16 App Router, next-intl (ru/en), Tailwind v4 только
как источник токенов. Прод — https://www.circleofdms.com, деплой на Vercel.
Полное описание проекта, доменов и DNS — в [README.md](README.md).

---

## Перед тем как сказать «готово»

```bash
npm run validate   # lint → i18n → build → seo, всё сразу
```

По отдельности: `build` (он же проверка типов), `lint`, `i18n` (сверка
`en.json` с эталонным `ru.json`), `seo` (аудит собранных страниц).

Оба должны пройти чисто. `build` ловит типы и ошибки пререндера, `lint` — то,
что build пропускает. Прогоняйте оба.

**Отсутствующий ключ перевода сборку НЕ роняет.** Проверено: билд завершается
с кодом 0 и лишь печатает `MISSING_MESSAGE: <ключ> (<локаль>)` в лог, а страница
собирается с испорченным текстом. Поэтому после правки `messages/*.json`
смотрите лог, а не только код возврата:

```bash
npm run build 2>&1 | grep -i MISSING_MESSAGE
```

Если правили что-то видимое — поднимите `npx next start -p 3111` и проверьте
страницу реально, а не «по коду». Скриншот без расширения Chrome снимается так:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars --virtual-time-budget=3000 \
  --window-size=1280,1700 --screenshot=out.png http://localhost:3111/privacy
```

Headless Chrome шлёт `Accept-Language: en` и уедет на английскую версию.
Для русской добавьте `--lang=ru-RU --accept-lang=ru-RU,ru`.

## Архитектура

Зависимости идут только вниз: `app/` (роутинг и метаданные) → `components/`
(презентация) → `lib/` (чистые функции) и `i18n/`. Компонент не знает про
роутинг, `lib/` не знает про React.

- **Страницы тонкие.** `page.tsx` разрешает локаль через `resolveLocale`,
  зовёт `setRequestLocale` и собирает секции. Разметку в страницу не писать —
  она живёт в компоненте.
- **Один компонент — один файл.** Секции лендинга лежат по файлам
  в `components/landing/`, наружу отдаются баррелем `index.ts`. Не сваливайте
  новые секции в существующий файл: раньше здесь был один `sections.tsx`
  на 396 строк, его разнесли осознанно.
- **Серверные компоненты по умолчанию.** `'use client'` в проекте один —
  `Rise.tsx`, ему нужен `IntersectionObserver`. Новый клиентский компонент
  заводить только под настоящий браузерный API и объяснять зачем.
- **Всё пререндерится.** Каждая страница объявляет `generateStaticParams`.
  Если в выводе `next build` страница помечена `ƒ` вместо `●`/`○` — это
  регрессия. Единственное законное исключение — `[locale]/[...rest]`:
  он ловит произвольные несуществующие пути, их множество бесконечно,
  пререндерить нечего. Не «чините» его.
- **Локаль сужается один раз.** Next отдаёт `params` со `string`, а next-intl
  после типизации требует `Locale`. Для этого есть `resolveLocale`
  из `@/i18n/params` — не приводите типы вручную и не пишите `as Locale`.
- **Повторяющиеся метаданные — в `lib/`.** Образец: `buildLegalMetadata`
  обслуживает обе правовые страницы.
- **UI-библиотек нет и не нужно.** Обоснование — в README, раздел
  «Почему здесь нет UI-библиотеки». Если считаете иначе — сначала спросите.

## Жёсткие правила

**Текст только в `messages/ru.json` и `messages/en.json`.** Никаких строк
в JSX. Ключи типизированы через `src/global.d.ts`, поэтому опечатка в `t('...')`
роняет сборку. Эталон — русский файл; расхождение с английским ловит
`npm run i18n`, добавляйте ключ сразу в оба. Файлы переживают round-trip через
`json.dumps(..., ensure_ascii=False, indent=2)` побайтово, так что массовые
правки удобно делать питоном.

**Навигация только через `@/i18n/navigation`.** `Link`, `redirect`,
`usePathname`, `useRouter` берутся оттуда, не из `next/link` и `next/navigation`.
Обычный `next/link` не подставит префикс локали, и со страницы `/en` ссылка
уведёт пользователя на русскую версию.

**Цвета только токенами.** `var(--color-brand)` и подобные из `globals.css`,
внутри `landing.css` — его шорткаты (`--acc`, `--t1`, `--bd`). Хардкод хекса
в новом коде недопустим.

**Адрес сайта только из `@/lib/site`.** Не хардкодить домен и не заводить
вторую константу: из `SITE_URL` собираются `metadataBase`, canonical, hreflang,
`sitemap.xml` и `robots.txt`. Раньше константа была продублирована в трёх
местах с фолбэком на несуществующий домен — не воспроизводите.

**Не трогать matcher в `src/middleware.ts` без понимания.** Исключение
`opengraph-image` там стоит намеренно, см. раздел «Грабли».

**`landing.css` портирован 1:1 из утверждённого макета.** Не рефакторить
и не «причёсывать» — он специально держится сравнимым с исходником.

## Дизайн-система

Источник правды — проект **ScRoll Design System** в Claude Design
(`978c02c7-475c-46b5-9a7d-8a7e896f4f15`), доступен через инструмент
`DesignSync`. Локально лежит его копия в `design-system/` (превью токенов
и компонентов в HTML) и выжимка в [docs/DESIGN-MODEL.md](docs/DESIGN-MODEL.md).
Токены из выжимки один в один перенесены в `@theme` в `src/app/globals.css` —
это то, чем реально пользуется код.

Правила, нарушать которые нельзя:

- **Тёмная тема единственная.** Светлой у продукта нет, не изобретайте.
- **Зелёный — единственный акцент.** `#22c55e` для акцентов и ссылок,
  `#15803d` для primary-кнопок. Остальные цвета палитры — только семантика
  (ошибка, предупреждение) и бейджи типов контента.
- **Ни одного цвета вне палитры**, кроме фотографий и скриншотов.
- **Шрифт Geist**, веса до 700, без black. Это шрифт приложения, он держит
  цельность бренда.
- **Радиусы:** карточки 16, кнопки и контролы 8–12, чипы — pill.
- **Motion сдержанный:** fade + rise 16–24px, 300–400ms, ease-out. Свечение
  пульсирует только в hero. Паралакса и каруселей быть не должно.
- **Иконки lucide**, тонкие, stroke 1.5–2px.
- **Скриншоты только настоящие**, из `public/screens/`. Рисованные фейки
  экранов запрещены.

Смысловая часть — в [docs/PRODUCT-CONTEXT.md](docs/PRODUCT-CONTEXT.md).
Оттуда обязательны §5 «Терминология» (мастер, а не ГМ; НРИ, а не настолки;
заявка, а не бронирование) и запрет старых названий бренда: **Circle of DMs,
CDMS и «Платформа Круга» в пользовательских текстах не употребляются**,
только ScRoll. Юрлицо в правовых текстах и разметке — CDM Software LLC.

## SEO

Полные правила — в [docs/SEO.md](docs/SEO.md), прочитайте перед любой правкой
метаданных, заголовков, ссылок или текстов. Проверяемая часть автоматизирована:

```bash
npm run build && npm run seo
```

Аудитор проверяет title и description, canonical, hreflang, og-теги, `lang`,
единственность `h1`, разрывы в иерархии заголовков, `alt`, ссылки-заглушки
и валидность JSON-LD. Ошибки роняют команду, предупреждения — нет, но
предупреждение нужно закрыть или осознанно оставить.

Коротко, самое важное:

- новая страница = `generateStaticParams` + `generateMetadata` с canonical
  и `languages` + путь в `PATHS` в `app/sitemap.ts` + входящая ссылка;
- один `h1` на страницу, иерархия заголовков без разрывов;
- **размечать в JSON-LD можно только то, что видно на странице** — иначе
  ручные санкции Google;
- `description` 70–160 символов, `title` до 60;
- страница в выводе `next build` должна быть `●` или `○`; появилась `ƒ` —
  это регрессия производительности, чините.

## Типовые задачи

**Добавить текст на существующую страницу.** Ключ в `messages/ru.json`
и `messages/en.json` → `useTranslations('namespace')` в компоненте. Массивы
и объекты достаются через `t.raw(key)` с явным приведением типа.

**Добавить страницу.** Каталог в `src/app/[locale]/<путь>/page.tsx`, внутри
`generateStaticParams` по `routing.locales`, `generateMetadata` с canonical
и `languages`, в компоненте `resolveLocale(params)` и `setRequestLocale(locale)`
первым делом. Затем путь в `PATHS` в `src/app/sitemap.ts` и ссылка в футер
(`components/landing/Footer.tsx`). Образец — `privacy/page.tsx`.

**Добавить секцию лендинга.** Новый файл в `components/landing/`, экспорт
в `index.ts` на нужной позиции, вставка в `[locale]/page.tsx`. Тексты —
в оба файла переводов.

**Поменять OG-картинку.** `src/app/[locale]/opengraph-image.tsx`. Текст на ней
пишите **латиницей**: дефолтный шрифт `ImageResponse` не покрывает кириллицу,
кириллица отрисуется квадратами. Ассеты читаются через `fs` от `process.cwd()`,
поэтому `generateStaticParams` обязателен — иначе роут станет динамическим
и чтение файлов уедет в serverless-рантайм.

**Проверить картинку без деплоя.** После `npm run build` готовый PNG лежит
в `.next/server/app/ru/opengraph-image.body` — скопируйте с расширением `.png`
и посмотрите.

**Search Console.** Уже подключён: Domain property `circleofdms.com`,
подтверждён TXT-записью от Google Workspace. Sitemap задаётся полным адресом
`https://www.circleofdms.com/sitemap.xml` — Domain-ресурс относительный путь
не принимает. Если понадобится отдельный URL-prefix ресурс, токен из способа
«HTML tag» вписывается в `GOOGLE_SITE_VERIFICATION` в `src/lib/site.ts`;
пустая строка = тега нет.

**Заменить иконку.** Исходник `assets/app-icon.png` (1024×1024). Из него
`sips`-ом делаются `src/app/favicon.ico` (64), `icon.png` (512),
`apple-icon.png` (180). Теги Next проставляет сам по файловой конвенции.

## Грабли, на которые уже наступали

**Middleware съедает `opengraph-image`.** При `localePrefix: 'as-needed'`
next-intl редиректит `/ru/opengraph-image` на `/opengraph-image`. Краулеры
соцсетей за редиректом для `og:image` не ходят и показывают карточку без
картинки. Общий фильтр matcher'а отсеивает пути с точкой в имени, а у этого
роута расширения нет — поэтому он вписан в исключения явно.

**Telegram кеширует превью надолго.** После правки метаданных карточка сама
не обновится. Быстрая проверка — отправить ссылку с другим query (`/?v=2`),
такой URL в кеше не лежит. Сброс кеша основного адреса — через бота
`@WebpageBot`.

**`localeDetection` включён.** Заход на `/` с `Accept-Language: en` редиректит
на `/en`. Из-за этого превью ссылки в Telegram выходит английским. Это принятое
решение, не баг — не «чините» без запроса пользователя.

**`docs/` и `design-system/docs/` — идентичные копии.** Правка одной не влияет
на другую.

## Деплой

**Пуш в `main` = деплой в продакшн.** Стейджинга нет. Поэтому:

- коммитить можно свободно;
- **пушить — только по явной просьбе пользователя**;
- любые правки публичных текстов (особенно правовых страниц) показывать
  пользователю до пуша.

Статус деплоя смотреть через Vercel API или `vercel --scope circleofddms-projects`.
Локальная папка не залинкована, скоуп нужен всегда.

## Мелочи

- Комментарии и сообщения коммитов — по-русски, как в остальном репозитории.
- Коммиты в стиле conventional (`feat:`, `fix:`, `chore:`), заголовок
  по-английски, тело по-русски с объяснением **почему**, а не что.
- Комментарий пишется, только когда объясняет неочевидное решение. Пересказ
  кода словами не нужен.
- `'use client'` в проекте ровно один — в `Rise.tsx`. Новый клиентский
  компонент заводить, только если правда нужен браузерный API.
- Экраны приложения в `public/screens/` — экспорт из Figma в 2x. Показывать
  через `components/landing/Screenshot.tsx`, родитель должен быть
  `position: relative` с `overflow: hidden`.
